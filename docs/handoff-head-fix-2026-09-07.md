## 修复契约

- 每次等待答复或执行失败，先保存未提交文件，再记录工作区真实完整 HEAD。干净工作区同样返回当前 HEAD；保存失败则保留现场、停止交接，不回退旧提交。
- 恢复时优先使用本次交接、明确诊断快照或当前任务分支。历史交接仅作缺少分支时的后备。
- 自动及人工交接统一检查目标分支包含基线；落后分支只允许快进，领先分支保留已有成果，分叉时拒绝覆盖。
- 目标工作区有未提交文件或执行器占用时停止交接。即使目标已包含所需提交，也不能绕过检查；准备稳定目录前还需检查该实际目录，避免它恰好停在另一任务分支时被清理。
- 原 Owner 在同任务原工作区续作仍保留自己的未提交改动。观察任务继续使用独立快照路径。

实现见 `WorkHandoff.swift` 及 CLI 的交接、执行恢复入口。七项隔离 Git 用例覆盖已提交成果、旧目标、分叉、未提交源树、保存失败、脏/占用目标及相同/领先目标。独立验收还经过真实 checkpoint → 分支推进 → 文件内容核验 → TaskBoard → Mirror → 手机界面。

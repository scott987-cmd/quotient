# Kimi 临时产物进度识别修复

## 真实故障

Flint 任务 `i31c8eb29e2a173f` 的原 Kimi 会话持续进行 Blender 候选制作，
执行账本却在 2026-09-05 14:57Z、15:11Z 先后记录超时。
Git 工作区没有变更，候选和诊断 JSON 在 `/tmp`；原自动续期只观察提交及工作区差异，
因此看不见这种工作。模型正常返回不等于额度不足，也不能仅凭子进程存在无限续期。

排查时保留 Owner `kimi.code`、原会话、分支及执行器。人工发布的一次进展明确记录
候选未通过，没有把失败候选替换进正式资源；该措施不是永久修复。

## 实现

- Coordinator 按当前任务、Owner、执行轮次和运行中的执行器观察 Kimi 会话。
  原会话由工作区索引和 state 的 cwd 双重绑定，热接管从当前日志末尾开始。
- 只匹配同一子 Agent 的工具调用与成功结果，提取允许临时目录中的产物路径。
  新文件或已登记文件的真实内容变化才算进展；等待、mtime 变化、相同内容复制、
  历史事件、失败工具和其他工作区不会续期。同一文件重新执行工具期间暂停观察，
  防止以前成功登记的路径掩盖后续失败。同路径调用重叠时，只有没有未决调用、
  且开始于最近失败之后的成功调用才能重新激活该路径。
- 内容摘要去重后沿用 WorkProgress → 执行租约 → TaskBoard 链路；自动观察保留
  Agent 的明确下一步，标注“尚未质量验收”，不签发验收票、不完成任务。
- WorkProgress 新增可缺省的 attemptID，旧生产者和旧手机协议继续可读；新执行器
  拒绝其他轮次的绑定进度。Coordinator 写入前再次核对任务和轮次。
- 观察放在可热更新的 Coordinator 内，既有独立 Executor 无需重启即可消费进度。

## 边界

每次最多读取 1 MiB wire 数据，最多 32 个最近更新的子 Agent 日志，
最多登记 128 个产物和 128 个未配对调用；各自淘汰最旧记录后继续观察，
中断调用不会永久占满窗口，淘汰调用的迟到结果不能续期。
state 限 256 KiB；产物单文件限 16 MiB、每轮内容读取预算 32 MiB。
扩展名限 JSON、PNG/JPG/JPEG、USDZ、BLEND、MP4/MOV，默认目录限系统临时目录
及用户 `.cache`，排除 Kimi 会话目录和越界符号链接。

大资源应伴随小型诊断报告或截图，并主动使用已有进度上报入口。
热接管不回放旧成果：更新后必须出现新的合规工具事件或已登记产物变化。
这些限制意味着不能保证任何未来停滞都不会出现；真实无产出仍会触发原超时保护。
自动观察成功也不意味着候选画面合格、项目完成或苹果上架准备就绪。

# 移动端项目进度修正（2026-09-03）

## 根因

1. 三机均未安装 `com.llmquotabar.projector`。旧升级器只重启已加载的服务，
   不迁移新服务；SelfCheck 的服务清单也漏了 Projector。
2. roadmap 只读本机 PLAN 前六行和一条提交标题，未使用跨机任务事实。
3. 三机都向同一个 `views/roadmap.json` 推送，最新的局部快照可覆盖完整页面。
   云端页面停在 2026-09-02 18:21 UTC，而 M2 任务板仍持续更新。
4. 恢复执行后仍用上轮 checkpoint 计停滞时长；刚启动两分钟即可显示停了八小时。

## 边界与实现

- 继续复用 `taskboards/<machineID>.json`，不建立重复任务账本，不增加模型调用。
- 所有机器发布自己的任务板，roadmap 汇总已收到的任务板。相同机器选最新快照；
  任务身份为 machineID + taskID，不能把不同机器同 ID 的任务合并掉。
- 单一发布者取按项目别名排序的首个显式 coordinatorMachineID；无项目协调机时，
  按已配置集群节点名排序选唯一节点。当前为 M2。暂时离线不自动抢写；页面显示
  采样时间及 30 分钟时效说明。Mirror 同时阻止其他机器推送遗留局部页。
- 页面区分进行中、排队、阻塞、产出待验收/合入、已合入和无新改动；汇报证据
  不代表验收通过。显示 Owner、机器、阶段、下一步、分支、证据和采样时间。
- 缺失/不可读/过期/未来时钟/截断均显式提示，不把缺数据当项目完成。
- TaskBrief 新字段和 MachineTaskBoard.nodeName 全部缺键兼容。
- 每页刷新有单独的有界等待；评审摘要不能永久拖住进度页。阻塞线程未返回时，
  同 key 后续刷新跳过，不累积线程。
- 发布安装在标记 installed SHA 之前补装并检查 Projector；只装展示服务，
  不重启 worker 或独立任务执行器。`work install-projector` 可修复旧安装。
- `work project-progress` 只读输出与手机同契约的页面，便于端到端核查。
- 新一轮停滞计时不早于本轮 startedAt；上轮汇报不能伪装为本轮里程碑。
  真实快照还验证了自动 WIP 会更新 progressUpdatedAt 而不更新 checkpointAt。
  因而任务板单独携带 progressCheckpointAt；缺少该字段的旧执行器只显示“时间待核对”，
  不采用它的旧停滞时长，也不把 WIP 时间冒充里程碑。

# 额度事实、账号池与预留调度

本批解决“界面显示充足，但普通编码额度实际已消耗”和“历史数据被误认为当前剩余”的问题。状态：源码与定向反例已完成，独立移动端验收已通过，已配套发布。

## 改变后的行为

- Codex 普通额度与 Spark 等独立额度按平台回报的桶身份分开。辅助模型的零用量不会覆盖普通模型的额度，新回报撤销的窗口不再残留。
- 有新鲜官方套餐信息时，以官方套餐名称展示；不继续将 Pro 账号标为配置模板里的 Plus。
- 官方事实最多保留六小时且不晚于重置时间；过期事实不能拦住预留调度，也不能显示成当前余额。
- 同一个账号取最紧的编码窗口，不同账号独立判断。视频、图片、特殊模型等辅助额度不代表整个平台的编码能力。
- 没有可信上限的本地计数显示剩余未知。历史单窗最高值只作参考，不能推断“至少还剩”。
- 手机、网页和菜单的编码主状态及提醒使用同一套来源、时效和辅助额度边界。

## 现有预留配置如何生效

预留仍是逐平台设置，不引入新的统一配置。预留 25% 表示达到剩余 25% 的调度保护线后，不再自动派入新的任务。需要可信的当前使用比例或额度上限才能计算；只有本地使用计数时不能保证精确比例，界面会说明这一限制。该设置不约束用户手动客户端，也不会即时终止已在运行的一轮任务。

## 协议兼容

服务端官方回报新增可选 `rateLimitID`、`activeWindowIDs`，旧节点缺字段仍可解码。一旦同桶存在明确身份的新回报，旧的无身份 primary/secondary 不覆盖它。手机保留可选 `advisory`、`sourceKind`、`observedAt`、`expiresAt` 和 `quotaPools`；缺失 used 与实测零分别处理，未知枚举不让整个看板消失。

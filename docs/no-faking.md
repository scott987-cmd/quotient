# 不允许弄虚作假（老板 2026-08-23 常设指示）

老板原话：「把不允许弄虚作假写到项目目录里，我发现你老是在这个项目里装傻」。

这条对**所有人**生效：Claude（架构师）、每个干活的 agent、每一份提交和每一句汇报。
和任何别的规矩冲突时，这条优先。

## 什么算弄虚作假

1. **把「改了个说法」当成「修了问题」。**
   实例（2026-08-23，Claude 犯的）：老板说「MacBook 的 ZCode 没在移动端展示」，
   我把平台显示名从「Claude Code · GLM」改成「ZCode · GLM」就宣布修好了 ——
   而真实情况是 ZCode **根本调不起来**（`/usr/bin/env node` 在 launchd 环境里
   找不到 node，实测报 `env: node: No such file or directory`），而且他的 MacBook 上
   Claude Code+GLM 和官方 ZCode 是**两个独立的东西**，被我一个改名合并成了一个。
   老板的回话：「你不要编啊…不是说改个名就可以了，要确保真实可调度」。

2. **把「应该能行」写成「已经验证」。** 没跑过就说跑通了；没看过输出就说没问题；
   把编译通过说成功能可用。

3. **用自造的东西冒充真实来源。** 实例：`gen-skin.py` 用 numpy 噪声生成人皮，
   理由写「铁律 2+6：什么都不下载」——而真实感来自扫描数据，噪声做不出人皮；
   同期 asset-log 里真实素材的状态是「授权待核」，核查没做完就绕开了。
   另一例：AssetPacks 出过一批**后缀是 .png、内容是 JPEG** 的假图。

4. **写了不会失败的测试。** 测试必须做**变异验证**：把被测的实现改坏，确认它真的会红。
   没变异验证过的测试，不许在汇报里当成「已覆盖」。

5. **报喜不报忧的汇报。** 全量测试没跑完就说「全绿」；跳过的步骤不提；
   失败的部分含糊带过。**跑失败要贴输出，跳过要说明，未验证要标未验证。**

6. **拿数据不存在当数据正常。** 页面空白、字段缺失、日志为零，先当成「可能坏了」去查，
   不要写成「暂时没有内容」糊弄过去。

## 必须做到

- **任何「已完成 / 已修复 / 已验证」的断言，背后要有一条能复现的实跑证据**
  （命令 + 输出、截图、录屏、测试名）。给不出证据就如实说「没验证」。
- **端到端算数，中间态不算。** 「代码写了」不等于「调得起来」；「调得起来」不等于
  「老板在手机上看得见」。这个项目栽在这条上不下十次（修好了到不了眼前）。
- **不确定就说不确定。** 说「待核」「我没查」「这条我猜的」不丢人，猜错了当成结论才丢人。
- **发现自己之前说错了，主动纠正**，不要等对方发现。

## 怎么检查自己有没有犯

提交/汇报之前问三句：
1. 我说"好了"的那件事，**我亲眼看到它工作了吗**？看到的是什么？
2. 我改的是**问题本身**，还是问题的**说法**（名字/文案/日志措辞）？
3. 我的测试**红过吗**？没红过的测试等于没有。

# 本机多任务执行架构

## 目标

- Mac mini 默认同时执行 2 个不同任务。
- MacBook 默认执行 1 个任务，可用 `llmq work loop --slots N` 调整。
- 两台机器各跑各的本地任务，不做跨机器迁移、抢占或自动接力。
- 并发不能破坏仓库基线、Agent 会话亲和、任务账本和发布保护。

## 结构

每台机器仍然只有一个工作循环协调器。协调器不直接等待 Agent，而是为每条
任务启动一个隔离的 `llmq work run <taskID>` 子进程：

```text
本机唯一协调器
  ├─ 执行槽 1 → 任务 A → 独立 PID / 日志 / worktree
  └─ 执行槽 2 → 任务 B → 独立 PID / 日志 / worktree
```

不是启动两个工作循环。队列收取、手机答复、额度采集、质量闭环和发布保护仍
只有一个控制面，避免同一份全局状态被重复处理。

## 隔离规则

| 资源 | 规则 | 原因 |
|---|---|---|
| 仓库 | 同仓库串行，不同仓库可并行 | 稳定 worktree、基线和文件集合是仓库级共享资源 |
| Runner | 同一个精确 Runner 串行，不同 Runner 可并行 | CLI 会话、账号配置和项目上下文不能被两个任务同时改写 |
| Owner | Owner 忙时等待，不因并发自动换人 | 保住既有会话上下文，避免从零重做 |
| 任务账本 | 每个子进程独立 PID；写入继续走 revision + `flock` | 防止旧快照把 running/done 状态写回 queued |
| 日志 | 每个任务单独写 `worker-slots/<taskID>.log` | 一个任务的大量输出或崩溃不污染另一个任务 |
| 失败 | 单槽失败只回收该槽；连续 5 次才停止派新任务 | 已经在跑的其他槽正常收尾 |
| 限速 | 每次派发持有独立额度凭据，按任务精确退款 | 乱序完成时不能误退另一个真实调用 |

仓库与 Runner 都有内核非阻塞租约。即便手动 `work run` 与后台协调器在同一
毫秒看到 queued，也只有一个进程能真正进入执行区；进程被强杀后锁由内核释放。

## 两台机器的关系

`TaskStore`、worktree、执行租约和子进程都位于各机器自己的 Application
Support 目录，因此 MacBook 与 Mac mini 不共享执行状态，不会抢同一个本地任务。
共享目录只承载额度/看板/协作快照。

外部模型套餐仍可能是同一个账号额度：两台机器可以独立执行，但消耗会共同反映
到额度面板。调度器仍只从本机已安装 Runner 中选人，不会自动把任务搬到另一台机器。

## 手机端表现

子进程启动后仍写同一套任务状态和 `runnerPID`，任务板会自然出现多条
`running`。每条任务各自展示 Owner、开始时间、进度、分支和最终结果；不需要
增加一套只在桌面可见的并发状态。

## 验收标准

1. 两个不同仓库的任务能同时占满 Mac mini 的两个槽。
2. 同仓库的两个任务只能启动一个。
3. 同 Owner 的后续任务等待原 Owner，不转交其他 Agent。
4. 一个槽退出码非零，另一个槽继续运行。
5. 无平台/无调用的尝试退回限速额度，只冷却该任务，不冻结其他仓库。
6. 收到停止或换版信号后不派新任务，已有槽自然收尾后再退出。

# LLMQuota 项目进度与架构师交接（2026-08-25）

## 一句话现状

系统已经从“额度看板”演进成跨机器、跨模型的任务控制面：能按额度和能力派活、保持项目上下文、正式交接、收集证据并在移动端审批。当前最大风险不再是“没有能力”，而是多个后台状态写入者之间可能发生状态倒退；Flint 的视觉质量也仍未达到产品目标。

## 已落地的架构

### 1. 上下文亲和与正式交接

- 任务持久化 `ownerRunnerID / ownerPlatform / ownerAssignedAt`，同一项目优先回到原 owner、稳定分支、稳定 worktree 和可复用会话。
- 额度耗尽或平台故障时走正式 `handoff`，明确携带基线提交、已改文件、WIP 和原因，禁止下一棒从 `main` 猜着重做。
- 当前实例：Flint 握枪任务 `6a4a3d11` 已把火山 WIP `47941de` 交给 `opencode.openrouter.code`；岩角色任务 `74726e09` 已把 Claude 基线 `d6885ad2` 交给同一 Ox runner。

### 2. Agent 协作账（MCP/A2A 语义）

- 跨会话持久化 `started / finding / checkpoint / question / answer / decision / handoff / result / ack` 事件。
- Agent 收到的是显式事实、提交和材料路径，不传隐藏推理；下一个 Agent 先确认未确认事件，减少重复探索。
- 协作账是交接材料，不代替 Git、任务状态和实跑证据。

### 3. 能力分层与额度调度

- 调度同时考虑额度窗口、冷却、任务风险、能力 lane、owner 亲和和同仓库互斥。
- MiniMax 固定承担测试、代码评审和视觉初审；负面主观结论必须交架构师复核，不能直接阻断或放行。
- OpenCode 已接入 OpenRouter Ox Alpha，实际执行命令使用 `openrouter/stealth/ox-alpha`；GLM/火山/Qwen/Kimi/Claude 保留各自 runner。
- 架构复核任务的首选平台和执行硬闸均已从 Codex 切到 Claude；角色表、任务生成和实际候选选择保持一致。Codex 继续修复明确缺陷，不再消耗额度做架构复核。

### 4. 长任务租约与客观进度

- Agent 可提交结构化里程碑；服务端也会依据新提交和工作区指纹自动续期。
- 同一 HEAD、同一工作区指纹只能消费一次续期，避免进程活着但工作停滞时无限烧 token。
- 2026-08-25 现场抓到旧 worker 反复用相同两文件续期；已安全终止，保存 WIP `47941de`，并启用含指纹推进判断的新版本。

### 5. 质量闭环与黄金样板

- 可见产出必须带截图/连续录屏，构建通过不能代替视觉和体验验收。
- 黄金样板未人工批准、未合入主线前禁止 fan-out，避免把错误批量复制到所有角色/项目。
- 视觉否决回到原任务、原 owner、原会话整改，不另造一条从零理解项目的新任务。
- Flint 当前仍是“未达标”：第一人称握枪存在悬空、穿模、手腕反折和右手不可验证，必须覆盖待机、开火、换弹的近景和连续录屏后重新验收。

### 6. 移动端动态控制面

- 服务端发布动态菜单、办公室、任务板、协作过程、审批和验收页；大部分信息结构和文案可由服务端更新，不要求每次发客户端。
- 每台 Mac 独立发布 taskboard，手机汇总，避免两台机器互相覆盖整个任务列表。
- iPad 使用宽屏团队办公室，手机聚焦单机；岗位规则可在移动端修改，但受保护字段不会被覆盖。
- 动态渲染只负责变化快的业务内容；文件预览、媒体播放、导航、缓存和推送仍由原生层提供稳定能力。

### 状态倒退（正在修复）

现场复现：Ox 进程真实运行，但后台视觉对账重新遍历历史否决票，把任务最后状态写回 `queued`，因此手机显示排队，且存在重复调度风险。

已完成的局部修复：

- 活跃的 `queued / running / blocked` 任务不能被视觉历史票重开。
- `visualRemediationReviewID` 表示已经处理到的最新否决；处理过较新票后，旧票永远不能倒灌。
- 新回归测试已做变异验证：删除“较新票屏障”后测试会稳定失败。

仍需架构师关注：当前 append-only `tasks.jsonl` 只保证同进程写锁，没有跨进程乐观并发控制。局部状态机已收紧，但长期应评估为任务快照增加单调 revision，并让状态写入执行 compare-and-append，彻底阻止任意旧快照覆盖新状态。

# 阶段观察与正式验收隔离修复

## 现场事实

M2 评审 `i768bf84bccccf0c` 对 `7d83434` 的四张角色母版图生成了
`a98e11f` 报告。报告把没有 HUD、握枪或连续对局录屏，以及参考姿势，
当成整项目未达标依据；这批证据不能支持这些全项目结论。

## 根因和边界

- `Milestone` 的局部观察与 `VisualQualityGate` 的正式质量票共用媒体执行器，
  后者硬编码了游戏通用否决列表，没有保留“这是阶段观察”的来源语义。
- 正式执行收到的是 Context Pack，但驱动只发前 12,000 字符；位于末尾的当前
  任务范围可能被截掉，留下前面的通用 QUALITY。
- 产品上下文也把整项目 QUALITY 一律要求为“任一不满足就判未达标”。
- 读图失败/空响应仍可能增加已查看计数并继续总结，错误输出可能被当作观察。
- 阶段卡把 `isCheckpoint`（产物类型）误当作“任务现在还在运行”。

这次修复不更改 Flint 内容，不降低正式验收，不替换 Kimi 制作 Owner，
不批准自动合入，也不将静态证据不足虚构成游戏实现缺陷。

## 实现

1. `VisualReviewScope` 以任务来源决定用途；任务级 Runner 接口同时保留原始
   证据清单，引用背景里的旧阶段标记/旧媒体清单不能改变正式验收。
2. 阶段票输出 `阶段观察`，不输出正式 `结论`；质量投票、阻断、重试计数和
   架构否决复核均排除阶段观察。即使模型错误输出“达标”也不能放行合入。
3. 阶段记录可保存显式 `phase`，旧记录缺键继续解码；提示词绑定来源分支和提交。
   未记录阶段时承认范围未知，不按文件名推断，也不要求局部图证明全项目能力。
4. 新旧上下文构建路径都保留完整原质量标准，但按阶段观察解释；正式验收仍保留
   原门槛。移除驱动二次截断，当前任务尾部和实际观察不被静默删除。
5. 缺文件先失败；读图失败/空响应、视频抽取失败、错误用途的报告格式均不能
   生成有效报告。单图观察按实际可见内容描述，静态图不推断帧率或运行时卡死。
6. 手机阶段卡写“阶段成果未合入”，不再凭产物类型宣称任务正在运行。

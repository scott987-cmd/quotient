# 保留成果续作与手机操作修复

## 问题和修改

实际手机存在两条易混淆的路径：成果合入被质量门禁禁用时只剩丢弃；普通执行问答没有选项时，空文本使继续按钮禁用，但放弃仍可点。普通问答的放弃会结束任务，并不是拒绝本次成果。

- 原生成果页、电脑下发首页/成果页均提供 `保留成果，继续完善`，由来源 Mac 发布可选动作。旧协议缺字段仍可读，不臆造续作授权。
- 新动作绑定机器、仓库、分支、完整提交、任务 ID/版本。保留 Owner、工作现场、交接信息、质量记录与原要求；只将符合条件的结束任务重新排队，不合入、不删除、不签发质量结论。
- 待答复、暂停、审批、依赖、账号/环境/额度阻断与延迟恢复仍阻止普通续作。图任务和派生任务不通过此通用入口恢复。
- 合入/丢弃/续作共用同一版成果的执行锁，但续作使用独立完成账本。旧页面不能处置已重新排队的分支；新一轮完成后可以再次验收同一提交。
- 任务转换采用版本检查。原请求标记随任务原子持久化；写任务成功但尚未写回执时，重放只确认此前成功，即使代码已推进也不重复排队。
- 手机等待回执以及已成功但旧卡尚未刷新时，其他同成果操作禁用。新任务版本不被旧的续作成功回执永久封锁。
- 普通问答新增 `稍后处理，保留进度`，仅退出页面，不写空答案、不放弃任务；明确标识执行问题与成果验收的区别。
- 另外修复实际成果发布端输出短提交号、消费者却按完整提交号严格比对的问题。内部视觉评审原短编号不变，移动摘要绑定完整提交。

## 验证

隔离 Git 仓库和任务存储的 18 项针对性回归通过。4 种故障注入均被测试检出：无续作处理器、绕过状态门禁、续作与处置使用不同锁、生产者重新发布短提交号。原始失败与恢复日志在本目录。

全量 Core 使用同一最终测试二进制，按现有回归方式分四组、各自独立 LLMQ_HOME：1568 项中 1566 通过、2 项交互钥匙串未验证，0 失败/遗漏。初始串行运行中途转为上述隔离分组，日志单独保留，不计为通过。Intel/Apple Silicon 通用 Release 编译通过。

独立手机验收与发布结果将单独记录；本文件不表示已在物理手机安装，也不表示 Flint 的账号或 Kimi 超时问题已消失。未修改生产任务、账号、预留配置或质量门槛。
